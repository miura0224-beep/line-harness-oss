# アカウント混在の調査・修正報告（2026-09-16）

## 結論

アカウントの表示とチャットの所属が一致しない不具合を、本番ブラウザーで再現した。画面と受信処理の修正は本番反映済み。ただし、保存構造の移行は追加承認待ちであり、全対応完了ではない。

## 確認した原因

1. アカウントの初期選択前に友だち・チャット一覧を取得でき、アカウント未指定の結果を表示し得た。
2. 切り替え前の非同期取得結果や選択中チャットが残り、切り替え後の画面へ混入し得た。
3. 個別チャットへの直リンクでは、別アカウントのチャットを一覧へ追加する処理があり、ヘッダーのアカウントは変更されなかった。本番で塾生アカウントのヘッダーとスリースターズの会話が同時に表示されることを確認した。
4. データベースはLINEユーザーIDを全アカウント共通で一意としていた。受信処理もIDだけで検索し、所属アカウントを書き換えていた。同じLINEユーザーIDが複数の公式アカウントで使われる場合、所属を誤変更する設計だった。

## 保存データ・受信経路の調査結果

- 3つの公式LINEについてWebhook URLと有効状態を確認。調査時点では正しい受信先で有効だった。
- 3アカウントとも当日21時台の受信記録を確認した。
- 問い合わせに対応する2つの個別チャットリンクは、どちらもスリースターズの友だちと会話履歴に結びついていた。履歴件数は20件と29件だった。
- アカウント情報のある送信ログと現在の友だち所属を比較した結果、不一致は0件。外部キー検査も違反0件だった。
- 過去の受信ログにはアカウント情報がないものがあるため、過去のすべての所属変更を否定できる調査ではない。
- 別の会員サービスへの紐付け情報と、LINEの友だち・チャットの存在は別項目として扱う必要がある。

## 本番へ反映した修正

- アカウントが確定するまで一覧ページを表示しない。
- アカウント変更時にページ内状態を作り直し、古い一覧・会話を残さない。
- 手動変更時に以前の個別チャット指定をURLから除去する。
- 個別チャットへの直リンクでは、会話の所属アカウントへ切り替えてから表示する。
- 古い取得結果による友だち一覧・チャット詳細の上書きを防止する。
- 受信、フォロー、送信記録、友だち取り込み等の友だち検索をアカウント単位に変更。所属の無条件上書きを撤去した。

- Webhook・送信プロキシ・友だち取り込みの関連テスト38件が成功。
- Worker型検査、Web本番ビルド、差分の空白検査が成功。

## 未完了：保存構造の移行

`packages/db/migrations/070_account_scoped_friends.sql` を用意した。友だちの一意性を「LINEユーザーID＋公式アカウント」に変更する。関連34テーブルの履歴を退避・復元し、移行前後の差分と外部キーを検査する。仮データによる検証は成功したが、本番には未適用。

自動承認審査により、本番DB全体のローカルバックアップと、バックアップ未取得の状態での親テーブル再構築が拒否された。前者は個人情報を含むデータの保存場所・範囲について明示的な承認が必要、後者は関連履歴を失うリスクが理由だった。

利用者へ、所有者だけが読める `/private/tmp/harness-account-audit-backup.sql` への本番DBバックアップと移行について追加承認を依頼済み。承認後、バックアップでの移行検証、本番適用、件数・履歴・外部キーの再検証を行う。

現時点の受信処理は誤った所属上書きを拒否するが、旧DBの一意制約は残る。同じLINEユーザーIDが別の公式アカウントに既に存在する場合、新しいアカウントの友だち登録が失敗する可能性が残っている。
